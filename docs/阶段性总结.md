# 阶段性总结：从 Reading Agent 平台收敛为文章阅读服务

更新日期：2026-08-27

## 当前定位

项目现阶段是“微信公众号文章抓取、SQLite 缓存、Markdown 阅读、可选 DeepSeek 摘要与 HTML/Markdown 导出服务”。

```text
URL → 安全抓取 / SQLite → 阅读投影 / Markdown → CLI、Web、MCP → 可选摘要与导出
```

它不再承担内部 Agent、知识库、评测平台或跨文章推理职责。知识笔记由调用方 Agent 基于阅读结果自行生成。

## 已完成的收缩

- 删除内部 Agent、Agent Run/SSE/Trace、知识库、评测、插件、多模型与旧数据兼容。
- 统一正文阅读：HTML 按需投影为内部 blocks，再由同一 Markdown 渲染器服务 CLI、MCP 和 Markdown 导出。
- MCP 仅保留 `ingest_article`、`get_cached_article`、`read_article`、`summarize_article`。
- `summarize_article` 改为 `article_id`，不再用 URL 隐式抓取。
- `ingest_article` 直接返回章节；失败以 MCP isError 上报；超大块在 20,000 以内整页返回。
- 删除 MCP 全文 Resource、搜索、图片清单、公开 block ID、content hash，以及无用的 FTS 写入、OpenTelemetry extra 与凭证 Fernet。
- 摘要只保留 DeepSeek 单次调用，输出 overview、key points、tags、one sentence；超过 `max_input_chars`（默认 50,000）直接提示分页阅读。
- 删除 TextRank、MapReduce、证据定位、摘要运行统计、摘要方法/风格选择和独立 `article_history` 表。
- 保留 Web、CLI、SQLite、分页阅读、HTML/Markdown 导出和批处理。HTTP MCP 使用 Streamable HTTP。

## 当前使用建议

| 场景 | 推荐路径 |
| --- | --- |
| 本地 Agent 可访问工作区 | `fetch --no-summary --export markdown`，直接读取 `.md` |
| 外部 Agent 无本地文件权限 | MCP：`ingest_article → read_article`；需要概览再 `summarize_article(article_id)` |
| 普通文章快速概览 | CLI/Web 可用 URL 摘要；MCP 先 ingest 再 summarize |
| 超长文章或多轮问答 | 使用分页 Markdown，由 Agent 自行归纳 |
| 人工查看或保真保存 | 导出 HTML |

## 验证状态

- SQLite Schema 只保留 `articles` 与 `summaries`；`article_fts` 由迁移删除。
- 2026-08-25 使用真实微信公众号文章验证了首次抓取（6,653 字）、SQLite 缓存命中和 Markdown 导出。验证未调用 DeepSeek，避免产生 API 成本。

本机 `.env` 若把默认导出目录配置到工作区外，验证或自动化时应显式传入 `--output .\\output\\article.md`，避免将可复现测试依赖于个人目录权限。已有本地库执行 `python -m wechat_article_reader db upgrade`。
