# 面试手册

适用场景：Python Agent 开发面试里被问到「还有个个人项目？」时，用 1～3 分钟讲清楚。本仓库**不是简历主力**，讲完边界比讲功能列表更重要。

## 开场（约 1 分钟）

「这是我自己用的学习项目，不是线上产品。我想让 Agent 能读微信公众号文章：页面不好抓、HTML 很脏、长文也不能整篇塞进上下文。

我做成一个小的内容交付服务：安全抓取，进 SQLite，再用同一套 Markdown 投影给 CLI、Web 和 MCP。本地 Agent 可以直接读导出的 md；外部 Agent 走 MCP。

我刻意没做内部 Agent。摘要只有 DeepSeek 一次调用，超长就失败，让模型自己分页读。这样我能讲清工具副作用，而不是演示一个聊天才发现不稳定的 Agent。」

## 两分钟可以补的三句话

1. **统一投影**：解析只发生一次，导出的文件和 MCP 的页是同一篇文章。
2. **副作用拆分**：ingest 才抓公众号；read 不联网；summarize 只打模型。
3. **长文策略**：默认给 H2 目录，按节跳读；不在服务端 MapReduce。我用三万字的文章试过 MCP，后来改的是阅读契约，不是加第五个工具。

## 关键追问

### 为什么 Markdown 是统一阅读格式？

同时适合模型和人，比 HTML 省 token，还能留标题和代码块。CLI 的 `.md` 和 MCP 分页必须是同一渲染器，否则面试官会问「两个入口哪个算对」。

### MCP 为什么分 ingest 和 read？

Agent 会重试。如果「读」也会抓网页，重试就是多次打公众号、多次写库。ingest 成功带回 UUID 和目录；read 只认 UUID。summarize 同样只认 ID。失败全部 isError，`code: 说明`，避免模型把 `{success:false}` 当成普通结果。

### 为什么保留分页，还删了搜索和 block ID？

分页是上下文预算。单篇阅读不需要搜索和对外 block 协议；多了就要兼容、测试、解释。内部仍有 blocks，只是不承诺。FTS 随搜索一起删掉，避免表还在写。

### 为什么长文摘要不分块？

MapReduce 能「交卷」，但调用次数、费用、中间失败和总结走样都要解释。这个项目交付原文页，超长让 Agent 按自己的问题去读，我可以对着原文核对。抓取上限可以比摘要上限宽：一个护磁盘，一个护上下文。

### 网页内容怎么算不可信？

正文里可能有「忽略以上指令」。抓取侧限制微信域名，做 SSRF、重定向、体积和 HTML 清洗；MCP 再标 untrusted。图片不下载、不做 OCR，也不声称看懂了图。

### 为什么 SQLite？

本地单用户，零运维。UUID + 内容 hash 够做缓存和摘要失效。多用户是存储端口以后的事，不是现在的架构目标。

### 你这个项目能说明你会做 Agent 吗？

能说明我会给 Agent **设计工具和上下文**。不能说明我实现过生产级 agent loop。loop、规划、多 Agent 请看别的经历；这个仓库请看交付和约束。

## 可指到的代码

- `ArticleReadingService`：ingest、分页、section、toc_level
- `MarkdownReadingRenderer` / `ArticleReadingProjector`：统一正文
- `mcp/toolsets/reading_tools.py` 与 `error_mapping.py`：契约和失败码
- `DeepSeekSummarizer` + `summarize_cached`：一次摘要、不再抓取
- 测试：`test_article_reading.py`、`test_mcp_reading_tools.py`

## 证据（不要说成大规模验证）

- 2026-08-25：约 6653 字真实文章，CLI 抓取、缓存、Markdown 导出；未打 DeepSeek。
- 2026-08-27：约 3 万字长文 MCP 阅读，推动目录默认深度、跳章和软分页。

## 讲的时候不要说的话

- 不要说「我做了一个 Agent 平台 / 知识库 / 评测系统」（已经删了，也不该恢复成卖点）。
- 不要说「支持任意网页」。
- 不要说「长文也会自动总结完整」——超长是失败，这是特性。
- 不要把 Cursor 当作用户量或生产 SLA。

## 当前边界（背下来）

- 仅微信公众号。
- 无 OCR、无图理解、无跨文章。
- 无 Key 时抓取和阅读可用，摘要明确失败。
- 超过摘要输入上限不截断、不分块。
