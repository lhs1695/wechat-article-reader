# 用法

根目录 [README](../README.md) 只留入口选择、真实返回体和设计取舍。阅读约定全文、CLI 全量命令、Web 页面和 MCP HTTP 鉴权在这里。

## 环境

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[web,mcp,dev]"
# 需要摘要时再加上 ai extra，或直接 pip install -e ".[full,dev]"
copy .env.example .env
python -m wechat_article_reader check
```

`.env` 里与摘要、抓取、目录相关的项见 [`.env.example`](../.env.example)。常用：

```env
WECHAT_ARTICLE_READER_DEEPSEEK__API_KEY=your-deepseek-api-key
WECHAT_ARTICLE_READER_DEEPSEEK__MAX_INPUT_CHARS=50000
WECHAT_ARTICLE_READER_RUNTIME_DIR=./.runtime
WECHAT_ARTICLE_READER_EXPORT__DEFAULT_OUTPUT_DIR=./output
```

- 抓取缓存上限 `SCRAPER__MAX_CONTENT_CHARS`（默认 50 万字）保护本地存储。
- 摘要输入上限 `DEEPSEEK__MAX_INPUT_CHARS`（默认 5 万字）保护模型上下文。两者可以不一致。

运行时数据在 `.runtime/`（SQLite、日志），导出默认在 `output/`。二者都是本机生成物，不要提交。已有旧库执行：

```powershell
python -m wechat_article_reader db upgrade
```

## CLI

入口：`python -m wechat_article_reader`。

```powershell
python -m wechat_article_reader check
python -m wechat_article_reader config
python -m wechat_article_reader config-init

# 抓取；默认可摘要。Markdown 导出默认无图，需要图时加 --images。
python -m wechat_article_reader fetch "https://mp.weixin.qq.com/s/example" --export markdown --output .\output\article.md
python -m wechat_article_reader fetch "https://mp.weixin.qq.com/s/example" --export html --output .\output\article.html
python -m wechat_article_reader fetch "https://mp.weixin.qq.com/s/example" --no-summary --export markdown --output .\output\article.md

# 终端阅读给人看；URL 首次会 ingest，UUID 只读缓存。默认一次最多 20000 字。
python -m wechat_article_reader read "https://mp.weixin.qq.com/s/example"
python -m wechat_article_reader read "ARTICLE_UUID" --cursor 12 --expected-revision "REVISION_UUID" --max-chars 8000
python -m wechat_article_reader read "ARTICLE_UUID" --section "结语" --output-format json
python -m wechat_article_reader read "ARTICLE_UUID" --images

python -m wechat_article_reader batch URL_1 URL_2 --export html
python -m wechat_article_reader web
# Windows 也可：双击 run_web.pyw（无控制台）或 run_web.cmd（有控制台）
python -m wechat_article_reader mcp-server
python -m wechat_article_reader mcp-server --transport http

python -m wechat_article_reader cache-stats
python -m wechat_article_reader db current
```

`cache-stats` 只读本机 SQLite：文章数、摘要条数、`created_at` 日期范围。库文件在 `.runtime/`，不要提交。旧文件名 `wechat_summarizer.db` 在尚未出现新库时仍会打开。

`read` 的 `--section` 返回该章及子章节；重名标题用 `--section-start-cursor`。续读必须带上一页的 `--expected-revision`；CLI 会打印可复制的下一页命令。不传 section 且全文不超过 `--max-chars`（默认 20000）则一次读完。默认不含图，需要图时加 `--images`。

## Web

三种启动方式都落到同一套 FastAPI 应用，监听 `http://127.0.0.1:8000`：

| 怎么开 | 说明 |
| --- | --- |
| `python -m wechat_article_reader web` | CLI；控制台打印 URL |
| `run_web.pyw` | Windows 双击；无控制台，就绪后打开浏览器；失败写仓库根目录 `error.log` |
| `run_web.cmd` | Windows 双击；用 `.venv\Scripts\python.exe`，有控制台 |

页面：首页状态、单篇抓取/摘要/下载、批量导出、历史（缓存列表）。HTTP JSON 与页面共用 `ArticleWorkflowService` / `ArticleReadingService`。

- `GET /api/article/markdown` 走与 MCP 相同的分页 Markdown 投影，**默认无图**（`include_images=false`）。
- 下载 Markdown 默认无图；下载 HTML 仍可带图。
- 页面里的「原文」展示清洗后的公众号 HTML。

### Markdown 阅读与导出格式

- 目标格式为 GFM：简单表格输出 Markdown，单元格换行使用 `<br>`；合并单元格和嵌套表格保留清洗后的 HTML。上下标也使用安全的 `<sub>` / `<sup>`。禁用 HTML 的阅读器可能无法显示这些布局。
- 代码块保留空格、Tab、空行、NBSP 和原 HTML 的语言标记。高亮 span 不增加换行，微信逐行 code / br 结构保持原有行序；代码围栏比内容中的反引号序列更长。
- 有序列表保留起始编号，相邻的独立列表通过安全注释分隔；嵌套列表、引用中的段落和代码保持结构。`b` / `i` 以及明确的 CSS 加粗、斜体、删除线、下划线转换为语义标记，其他 CSS 不输出。
- 普通文字只在对应 Markdown 上下文中转义，链接标签与实体保持字面含义。纯文本输入会先进行 HTML 转义。
- 普通段落优先在句子或空白边界分块，避免切断英文单词；导出会合并回原段落。标题、代码、表格和嵌套容器不会按 900 字截断。阅读接口完整 Markdown（包括文头）遵守 20000 字硬上限，超出时用 `export_article` 获取文件。
- 导出标题会与正文开头的同名标题去重；front matter 对标题、作者、URL、标签统一转义。跨 span 拼成的 Markdown 符号和字面 `~~` 正常转义；相对链接、页内锚点按文章来源 URL 解析。
- 图片保留正文中的相对顺序。有图版提供链接和说明，不执行 OCR 或图片理解；无图版省略图片标记，保留正文和可用图注。短数字、大写词和推荐结尾均保留，疑似推荐内容通过阅读元数据提示。

## MCP

给 Agent 用。要整篇 Markdown 落盘：`ingest_article` → `export_article`（绝对路径，成功体不含正文）。`read_article` 只把一页或一节读进上下文。五个工具及副作用见根目录 README。传输：本地 Cursor 默认 **stdio**；也支持本机 **Streamable HTTP**。

```text
ingest_article(url)
    → 返回 article_id、标题、字数、block_count、sections（默认 H2）
    → 整篇落盘：export_article(article_id, path)
    → 读进上下文且字数不超过 max_chars（默认 20000）：一次 read_article(article_id)
    → 更长且只要一节：read_article(article_id, section=...)
    → 该节仍超长才原样调用响应的 next_read
    → 需要通读概览时 summarize_article(article_id)
```

### 阅读约定

- 不传 `section` 时，全文不超过 `max_chars` 就一次返回，不要先翻页。
- 整篇文件用 `export_article`；`path` 必须是绝对 `.md` 路径或已存在的目录。
- `section` 返回该章及子章节。首次跳章 `cursor=0`；重名或超长标题可用 `section_start_cursor`，两种选择器不能同时传。续读 cursor 不在章内时明确报错，章末读取不会重新回到章首。
- ingest 的 `sections` 若只有「正文」（没有可用标题），不要按节跳；超长再跟随 `next_read`。
- `cursor` 是内容块索引；续读原样传响应中的 `next_read`，其中包含 `expected_revision`。旧客户端只传 `next_cursor` 需要升级。文章变化返回 `article_changed`；重新获取元数据并从头或章节开头阅读，不能继续使用旧块索引。
- 单块连同文头超过当前 `max_chars` 但不超过 20,000 会整块返回；完整页超过硬上限才 `page_too_large`。限制对象是 `content_markdown`，不是整个 JSON 响应。
- 分页尽量在标题前收束，连续列表尽量整组翻页。
- 响应含 `revision`、`block_count`、`word_count`（本页投影正文）、`chars`。`sections_in_page` 列出本页涉及的章节，`section_title` 仅描述页首。`reading_scope` 区分全文与章节；`has_more=false` 表示当前范围结束，`end_of_article` 表示是否到达文章末尾。合成节名「正文」不会作为续页标题插入。
- `image_count` 是扫描范围内的图片数，`omitted_images` 是无图模式省略数；`image_content_read` 始终为 false。图中文字未进入上下文，提示见 `content_notes`。
- `get_cached_article` 返回 `first_cached_at`（首次缓存）、`fetched_at`（最近抓取）、`summary_generated_at` 及 `summary_generation`（模型、长度、提示词版本和输出预算等）。摘要更新时间不再冒充抓取时间。
- 失败是 MCP **isError**，消息形如 `code: 说明`。超长错误附 `recovery` JSON，含 `export_article` 的完整参数；版本变化附重新获取元数据的参数。
- 五个工具成功体都带 `source_trust: "untrusted_web_content"`；网页正文（及据此生成的摘要）不能改写系统指令。

单独启动 MCP：

```powershell
python -m wechat_article_reader.mcp
python -m wechat_article_reader.mcp --transport http --port 8001
```

HTTP 模式默认绑 `127.0.0.1`，端口默认 `8001`。非本机监听必须同时使用 `--allow-remote` 和 `WECHAT_ARTICLE_READER_MCP_AUTH_TOKEN` / `--auth-token`（请求头 `X-MCP-Token`）；缺少令牌时拒绝启动。远程 HTTP 的 `export_article` 只能写入 `WECHAT_ARTICLE_READER_EXPORT__DEFAULT_OUTPUT_DIR` 指定目录及其子目录。本机 stdio 和本机 HTTP 仍可使用任意绝对 `.md` 路径。

刷新文章正文后，旧摘要不再算当前摘要；需要摘要时重新调用 `summarize_article`。抓取时每一跳重定向都必须仍指向 `mp.weixin.qq.com`。阅读与 Markdown 导出会转义普通网页文字中的 Markdown 语法，真实 HTML 链接仍保留为链接。

摘要以精确原文版本和生成条件为依据，相同条件重复调用复用已生成摘要；修改 `max_length` 等条件会重新生成。模型截断、未正常完成或缺少结构字段会失败。SDK 重试关闭，应用层重试遵守 `DEEPSEEK__TOTAL_TIMEOUT`（默认 180 秒）总预算，每次请求仍受 `DEEPSEEK__TIMEOUT` 限制。

取消 MCP 操作会通知后台工作，阻止后续重试与缓存/文件提交；已发出的同步 HTTP 请求只能等待结束后响应取消。缓存命中只做静态 URL 校验，不依赖 DNS；实际抓取仍逐跳执行 DNS 与 SSRF 校验。查询参数顺序不再造成重复文章身份。

数据库会自动迁移到 `20261014_03`。升级前建议备份 SQLite（运行中请用 SQLite backup API，或停止服务后完整备份数据库与 WAL）。旧 UUID 保留；等价 URL 的查询选择最近更新的记录，其他快照仍可用旧 UUID 读取。旧摘要作为历史记录保留，但不再认定与新精确版本一致，需要重新生成。
