# 用法

根目录 [README](../README.md) 只留入口选择、真实返回体和设计取舍。阅读约定全文、CLI 全量命令、Web 页面和 MCP HTTP 鉴权在这里。

## 环境

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[web,mcp,dev]"
# 需要摘要时再加上 ai extra，或直接 pip install -e ".[full,dev]"
copy .env.example .env
python -m wechat_article_reader check
```

`.env` 里与摘要、抓取、目录相关的项见 [`.env.example`](../.env.example)。常用：

```env
WECHAT_ARTICLE_READER_DEEPSEEK__API_KEY=your-deepseek-api-key
WECHAT_ARTICLE_READER_DEEPSEEK__MODEL=deepseek-flash
WECHAT_ARTICLE_READER_DEEPSEEK__MAX_INPUT_CHARS=50000
WECHAT_ARTICLE_READER_RUNTIME_DIR=./.runtime
WECHAT_ARTICLE_READER_EXPORT__DEFAULT_OUTPUT_DIR=./output
```

- 抓取缓存上限 `SCRAPER__MAX_CONTENT_CHARS`（默认 50 万字）保护本地存储。
- 摘要输入上限 `DEEPSEEK__MAX_INPUT_CHARS`（默认 5 万字）保护模型上下文。两者可以不一致。
- 当前默认模型为 `deepseek-flash`（DeepSeek-V4.1-Flash）；旧标识 `deepseek-v4-flash` 已退役并由服务端兼容路由。参见 [DeepSeek 官方模型说明](https://api-docs.deepseek.com/guides/codex)。

运行时数据在 `.runtime/`（SQLite、日志），导出默认在 `output/`。二者都是本机生成物，不要提交。已有旧库执行：

```powershell
python -m wechat_article_reader db upgrade
```

## CLI

入口：`python -m wechat_article_reader`。

```powershell
python -m wechat_article_reader check
python -m wechat_article_reader config
python -m wechat_article_reader config-init

# 抓取；默认可摘要。Markdown 导出默认无图，需要图时加 --images。
python -m wechat_article_reader fetch "https://mp.weixin.qq.com/s/example" --export markdown --output .\output\article.md
python -m wechat_article_reader fetch "https://mp.weixin.qq.com/s/example" --export html --output .\output\article.html
python -m wechat_article_reader fetch "https://mp.weixin.qq.com/s/example" --no-summary --export markdown --output .\output\article.md

# 终端阅读给人看；URL 首次会 ingest，UUID 只读缓存。默认一次最多 20000 字。
python -m wechat_article_reader read "https://mp.weixin.qq.com/s/example"
python -m wechat_article_reader read "ARTICLE_UUID" --cursor 12 --expected-reading-revision "rp1:ARTICLE_REVISION" --max-chars 8000
python -m wechat_article_reader read "ARTICLE_UUID" --section "结语" --output-format json
python -m wechat_article_reader read "ARTICLE_UUID" --images

python -m wechat_article_reader batch URL_1 URL_2 --export html
python -m wechat_article_reader web
# Windows 也可：双击 run_web.pyw（无控制台）或 run_web.cmd（有控制台）
python -m wechat_article_reader mcp-server
python -m wechat_article_reader mcp-server --transport http

python -m wechat_article_reader cache-stats
python -m wechat_article_reader db current
```

`cache-stats` 只读本机 SQLite：文章数、摘要条数、`created_at` 日期范围。库文件在 `.runtime/`，不要提交。旧文件名 `wechat_summarizer.db` 在尚未出现新库时仍会打开。

`read` 的 `--section` 返回该章及子章节；重名标题用 `--section-start-cursor`。首次阅读和续读都必须带 metadata 返回的 `reading_revision`（参数 `--expected-reading-revision`）；CLI 会打印可复制的下一页命令。不传 section 且全文不超过 `--max-chars`（默认 20000）则一次读完。默认不含图，需要图时加 `--images`。

## Web

三种启动方式都落到同一套 FastAPI 应用，监听 `http://127.0.0.1:8000`：

| 怎么开 | 说明 |
| --- | --- |
| `python -m wechat_article_reader web` | CLI；控制台打印 URL |
| `run_web.pyw` | Windows 双击；无控制台，就绪后打开浏览器；失败写仓库根目录 `error.log` |
| `run_web.cmd` | Windows 双击；用 `.venv\Scripts\python.exe`，有控制台 |

页面：首页状态、单篇抓取/摘要/下载、批量导出、历史（缓存列表）。HTTP JSON 与页面共用 `ArticleWorkflowService` / `ArticleReadingService`。

- `POST /api/article/fetch` 显式抓取并缓存，支持 `{ "url": "https://mp.weixin.qq.com/s/...", "refresh": true }`；响应给出 `article_id`、`revision`、`reading_revision` 和 `projection_version`。
- `GET /api/article/markdown` 只读缓存，必须传 `article_id` 与 `expected_reading_revision`，可选 `cursor`、`max_chars`、`section_start_cursor`、`include_images`；**默认无图**。版本变化返回 HTTP 409 和 `reading_changed`，重新 POST fetch 取得最新身份后从头阅读。
- `POST /api/article/summarize` 与 `/api/article/export` 使用 `{ "article_id": "...", "expected_revision": "..." }`，只操作该缓存版本，不接受 URL 或客户端回传摘要作为数据源。刷新需先调用 POST fetch 并使用新响应身份。
- 下载 Markdown 默认无图；下载 HTML 仍可带图。
- 页面里的「原文」展示清洗后的公众号 HTML。

### Markdown 阅读与导出格式

- 目标格式为 GFM：简单表格输出 Markdown，单元格换行使用 `<br>`；合并单元格和嵌套表格保留清洗后的 HTML。上下标也使用安全的 `<sub>` / `<sup>`。禁用 HTML 的阅读器可能无法显示这些布局。
- 代码块保留空格、Tab、空行、NBSP 和原 HTML 的语言标记。高亮 span 不增加换行，微信逐行 code / br 结构保持原有行序；代码围栏比内容中的反引号序列更长。
- 有序列表保留起始编号，相邻的独立列表通过安全注释分隔；嵌套列表、引用中的段落和代码保持结构。`b` / `i` 以及明确的 CSS 加粗、斜体、删除线、下划线转换为语义标记，其他 CSS 不输出。
- 普通文字只在对应 Markdown 上下文中转义，链接标签与实体保持字面含义。纯文本输入会先进行 HTML 转义。
- 普通段落优先在句子或空白边界分块，避免切断英文单词；导出会合并回原段落。标题、代码、表格和嵌套容器不会按 900 字截断。阅读接口完整 Markdown（包括文头）遵守 20000 字硬上限，超出时用 `export_article` 获取文件。
- 导出标题会与正文开头的同名标题去重；front matter 对标题、作者、URL、标签统一转义。跨 span 拼成的 Markdown 符号和字面 `~~` 正常转义；相对链接、页内锚点按文章来源 URL 解析。
- 图片保留正文中的相对顺序。有图版提供链接和说明，不执行 OCR 或图片理解；无图版省略图片标记，保留正文和可用图注。短数字、大写词和推荐结尾均保留，疑似推荐内容通过阅读元数据提示。

## MCP

给 Agent 用。要整篇 Markdown 落盘：`ingest_article` → `export_article`（绝对路径，成功体不含正文）。`read_article` 只把一页或一节读进上下文。工具及副作用见根目录 README。传输：本地 Cursor 默认 **stdio**；也支持本机 **Streamable HTTP**。

```text
ingest_article(url)
    → 返回 article_id、标题、字数、block_count、sections_page / images_page（默认各 20 项）
    → 大目录或图片清单：分别原样调用对应 page.next，使用 get_cached_article 续取
    → 整篇落盘：export_article(article_id, path)
    → 读进上下文且字数不超过 max_chars（默认 20000）：一次 read_article(article_id)
    → 更长且只要一节：read_article(article_id, section=...)
    → 该节仍超长才原样调用响应的 next_read
    → 需要通读概览时 summarize_article(article_id)
```

### 阅读约定

#### 阅读契约迁移

**4.0.0 破坏性契约升级。** 以下形状已升级为文章身份 + 阅读投影版本。旧调用必须迁移；不再接受旧阅读参数或按 URL 隐式抓取的 GET：

| 旧调用 | 新调用 |
| --- | --- |
| MCP `read_article(article_id, cursor=...)` 或传 `expected_revision` | 首次读取也传 `expected_reading_revision`；从 `get_cached_article` / `ingest_article` 取值，后续直接原样传 `next_read` |
| MCP `read_article_image(..., expected_revision=...)` | 传该文章当前的 `expected_reading_revision` |
| CLI `--expected-revision REVISION` | CLI `--expected-reading-revision rpN:REVISION`；命令会打印下一页参数 |
| Web `GET /api/article/markdown?url=...` | 先 `POST /api/article/fetch`，再以返回的 `article_id` 与 `reading_revision` 调 `GET /api/article/markdown` |
| Web summarize / export body 以 `url` 标识文章 | 以 `article_id` + `expected_revision` 标识已缓存快照；客户端不得提交摘要正文覆盖服务端摘要 |

MCP 阅读参数迁移：

```text
# 旧版：只用文章 revision，且首次 cursor=0 可省略版本参数
read_article(article_id, cursor=next_cursor, expected_revision=article_revision)
read_article_image(article_id, image_id, expected_revision=article_revision)

# 4.0.0：必须把 ingest_article / get_cached_article 的 reading_revision 传给两项工具
read_article(article_id, expected_reading_revision=reading_revision, cursor=next_cursor)
read_article_image(article_id, image_id, expected_reading_revision=reading_revision)
```

Web 完整调用示例（4.0.0 起）：

```http
POST /api/article/fetch
Content-Type: application/json

{"url":"https://mp.weixin.qq.com/s/example","refresh":false}
```

将返回的身份用于分页读取：

```http
GET /api/article/markdown?article_id=ARTICLE_UUID&expected_reading_revision=rp2%3AARTICLE_REVISION&cursor=0
```

续读时将 `cursor` 换成上一页的 `next_cursor`，并保持同一 `expected_reading_revision`。HTTP 409 `reading_changed` 表示缓存文章或投影版本已变化；响应提供 `current_reading_revision` 和重新 fetch 的恢复动作。`request_id` 同时出现在响应体和 `X-Request-ID` 响应头，可用于定位服务端日志。MCP 客户端仍使用六个既有工具及各自职责，不新增工具。

- 不传 `section` 时，全文不超过 `max_chars` 就一次返回，不要先翻页。
- 整篇文件用 `export_article`；`path` 必须是绝对 `.md` 路径或已存在的目录。
- `section` 返回该章及子章节。首次跳章 `cursor=0`；重名或超长标题可用 `section_start_cursor`，两种选择器不能同时传。续读 cursor 不在章内时明确报错，章末读取不会重新回到章首。
- ingest 的 `sections_page.items` 若只有「正文」（没有可用标题），不要按节跳；超长再跟随 `next_read`。
- `cursor` 是内容块索引；续读原样传响应中的 `next_read`，其中包含 `expected_reading_revision`。旧客户端只传 `next_cursor` / `expected_revision` 需要升级。文章或投影规则变化返回 `reading_changed`；重新获取元数据并从头或章节开头阅读，不能继续使用旧块索引。
- 单块连同文头超过当前 `max_chars` 但不超过 20,000 会整块返回；完整页超过硬上限才 `page_too_large`。MCP 完整工具结果（文本与结构化内容封装）另有 128 KiB UTF-8 字节上限；超预算时自动缩短正文页并以实际 `next_read` 为准，不能拆分的超大块提示改用 `export_article`。
- 分页尽量在标题前收束，连续列表尽量整组翻页。
- 响应含 `revision`、`block_count`、`word_count`（本页投影正文）、`chars`。`sections_in_page` 最多列出 20 个本页章节，超出的数量见 `omitted_sections`，完整目录可从 `get_cached_article` 分页穷尽；`section_title` 仅描述页首。`reading_scope` 区分全文与章节；`has_more=false` 表示当前范围结束，`end_of_article` 表示是否到达文章末尾。合成节名「正文」不会作为续页标题插入。
- `image_count` 是扫描范围内的图片数，`omitted_images` 是无图模式省略数；`image_content_read` 始终为 false。图片引用以 `images.items` 返回，超出当前阅读页引用范围时按 `images.next` 调用 `get_cached_article` 续取。图中文字未进入上下文，提示见 `content_notes`。
- `get_cached_article` 返回 `first_cached_at`（首次缓存）、`fetched_at`（最近抓取）、`summary_generated_at` 及 `summary_generation`（模型、长度、提示词版本和输出预算等）。`sections_page` 与 `images_page` 可用独立游标续取；过长标题、URL、alt 或 caption 会给出 UTF-8 安全预览并标记 `truncated`。摘要更新时间不再冒充抓取时间。
- 阅读和摘要结果的 `content_notes` 是 `{code, message, scope}` 列表，只陈述有证据的范围限制，例如安全清理移除嵌入媒体、来源字段缺失或图片未被读取。短正文不会自动判成截断，不提供无依据的完整度百分比；摘要只依据可读取的文字与可用图注。
- 失败是 MCP **isError**，消息形如 `code: 说明`。超长错误附 `recovery` JSON，含 `export_article` 的完整参数；版本变化附重新获取元数据的参数。
- 工具成功体标记 `source_trust: "untrusted_web_content"`；网页正文、图片与摘要均不能改写系统指令。

### 配图显示、下载与视觉阅读

三个开关默认关闭、互不隐式触发：

| 操作 | 参数 | 效果 |
| --- | --- | --- |
| Markdown 显示图片 | `include_images=true` / CLI `--images` | 保留图片标记，未下载时仍是远程链接 |
| 保存离线配图 | `download_images=true` / CLI `--download-images` | 将正文配图下载到同名 `.assets` 目录，写 `manifest.json`；显示开关仍可为 false |
| 给模型提供图像 | `read_article_image(..., send_to_model=true)` | 返回真正的 MCP 图像内容块；不自动下载，也不调用第三方视觉服务 |

```powershell
python -m wechat_article_reader fetch "https://mp.weixin.qq.com/s/xxx" --no-summary --export markdown --output "output/article.md" --images --download-images
```

本地导出是 `article.md` + `article.assets/manifest.json` + 版本目录中的图片。Markdown 使用相对路径，移动时须一起携带 `.assets`。清单包含 `article_id`、`revision`、图片编号、正文块位置、原始 URL、图注、真实 MIME、本地路径及成功/失败状态。同图重复引用只下载一次。文件名基于实际图片内容，路径中的空格或中文在 Markdown 引用中编码。图片下载失败保留远程链接，Markdown 明确提示离线包不完整。无图导出也会生成图片清单和资源，只省略正文图片标记。

Web 单篇页面提供“Markdown 显示图片”和“下载配图”两个独立选项。下载配图只适用于包含正文的 Markdown，浏览器得到 ZIP，内含 Markdown、清单及本次成功的图片；普通下载仍是单个文件。API `POST /api/article/export` 同样接受 `include_images`、`download_images`。

Agent 使用 MCP 的图文阅读流程：

1. `ingest_article` 后使用 `read_article` 阅读文字；页面 `images.items` 给出部分图片编号和所在 `block_cursor`。按 `images.next` 可续取本页更多引用；完整图片清单从 `images_page` 穷尽，无图模式也保留图片编号与位置。`content_notes` 会标明图片未被读取。
2. 用该页 `reading_revision` 作为 `expected_reading_revision`。首次需要网络下载时，调用 `read_article_image(article_id, image_id, expected_reading_revision, download_image=true, send_to_model=true)`。
3. 图片已缓存时可用 `download_image=false, send_to_model=true`，只提供本地图像。只下载但不提供则用 `download_image=true, send_to_model=false`；两个选项均 false 时仅返回元数据。
4. 客户端和模型必须支持 MCP 图像内容。返回 `image_content_provided=true` 只表示工具已提供图像，不断言客户端转发或模型已理解。纯文本 `read_article` 的 `image_content_read` 仍为 false。
5. 要求完整图文理解时，逐张核对全篇 `images` 清单，明确记录已提供、未提供或失败的图片；文字分页结束不等于图文理解完成。导出 Markdown 给本地 Agent 时，也必须让它显式用图片查看工具打开本地引用。

图片只允许 HTTPS 的 `mmbiz.qpic.cn`、`mmbiz.qlogo.cn`、`mmsns.qpic.cn`，逐跳做域名、DNS、SSRF 校验；不接受任意图片 URL。单图最多 10 MiB、2500 万像素；动画最多 200 帧、总计 1 亿像素。单篇下载最多尝试 100 个不同 URL / 50 MiB 输出资源，重复失败的 URL 不反复请求。校验实际文件，支持 PNG/JPEG/GIF/WebP；SVG、损坏图和超限图明确失败。下载动画保存原始文件；向视觉模型提供动画时仅返回首帧 PNG 预览（最长边 2048 像素），元数据 `visual_scope=first_frame` 明确其他帧未覆盖。图片缓存位于 `.runtime/images`，不写入 SQLite 正文，不提交到仓库。单图网络超时 20 秒；取消阻止后续请求和原子文件提交，已完成的缓存/资源可能保留以便复用。

单独启动 MCP：

```powershell
python -m wechat_article_reader.mcp
python -m wechat_article_reader.mcp --transport http --port 8001
```

HTTP 模式默认绑 `127.0.0.1`，端口默认 `8001`。非本机监听必须同时使用 `--allow-remote` 和 `WECHAT_ARTICLE_READER_MCP_AUTH_TOKEN` / `--auth-token`（请求头 `X-MCP-Token`）；缺少令牌时拒绝启动。远程 HTTP 的 `export_article` 只能写入 `WECHAT_ARTICLE_READER_EXPORT__DEFAULT_OUTPUT_DIR` 指定目录及其子目录。本机 stdio 和本机 HTTP 仍可使用任意绝对 `.md` 路径。

刷新文章正文后，旧摘要不再算当前摘要；需要摘要时重新调用 `summarize_article`。抓取时每一跳重定向都必须仍指向 `mp.weixin.qq.com`。阅读与 Markdown 导出会转义普通网页文字中的 Markdown 语法，真实 HTML 链接仍保留为链接。

摘要以精确原文版本和生成条件为依据，相同条件重复调用复用已生成摘要；修改 `max_length` 等条件会重新生成。模型截断、未正常完成或缺少结构字段会失败。SDK 重试关闭，应用层重试遵守 `DEEPSEEK__TOTAL_TIMEOUT`（默认 180 秒）总预算，每次请求仍受 `DEEPSEEK__TIMEOUT` 限制。

取消 MCP 操作会通知后台工作，阻止后续重试与缓存/文件提交；已发出的同步 HTTP 请求只能等待结束后响应取消。缓存命中只做静态 URL 校验，不依赖 DNS；实际抓取仍逐跳执行 DNS 与 SSRF 校验。查询参数顺序不再造成重复文章身份。

数据库会自动迁移到 `20261014_03`。升级前建议备份 SQLite（运行中请用 SQLite backup API，或停止服务后完整备份数据库与 WAL）。旧 UUID 保留；等价 URL 的查询选择最近更新的记录，其他快照仍可用旧 UUID 读取。旧摘要作为历史记录保留，但不再认定与新精确版本一致，需要重新生成。
